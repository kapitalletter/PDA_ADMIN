# 관리자 기능 점검 결과 — 2026-10-27

계정관리에서 실패 메시지가 숨겨져 제출 버튼이 무반응처럼 보일 수 있는 결함을 수정했습니다. 전체 기능은 React DOM과 모의 API를 연결한 기능 테스트 18개, 보안·API 테스트 43개를 통과했습니다. 실제 서버의 계정 인증과 데이터 저장 성공까지 확인한 결과는 아닙니다.

## 계정관리에서 확인한 원인과 수정

- `OwnerAccounts`는 오류를 상태에 저장하지만 화면에 표시하지 않았습니다. 약한 임시 비밀번호, 중복 계정, 서버 오류가 발생해도 사용자는 실패 사유를 볼 수 없었습니다. 이제 생성·수정·삭제 창 안에 오류를 표시하고 다시 시도할 수 있습니다.
- 연락처가 숫자 9~11자리로 제한되어 `010-1234-5678` 같은 입력이 브라우저 검증에서 막혔습니다. 표준 하이픈 형식도 입력할 수 있게 하고, 요청할 때 기존 API 전송 형식인 숫자로 정리합니다. 잘못된 구분자와 길이는 계속 차단합니다.
- 브라우저의 필수값·형식 검증 오류도 입력창 안에 표시합니다. 임시 비밀번호 조합 안내를 현재 프론트 검증 규칙에 맞게 구체화했습니다.
- 모달에 화면 높이 제한과 내부 스크롤을 추가했습니다. 작은 화면에서 하단 버튼에 접근할 수 있도록 한 코드 수정이며, 실제 브라우저의 시각 검수는 별도로 필요합니다.
- 저장 중에는 중복 제출·닫기·취소를 막습니다. 계정 생성 완료 창의 `확인` 버튼이 정상적으로 닫히는 것을 DOM 테스트로 확인했습니다.
- 마지막 페이지의 마지막 계정 삭제 후 유효한 페이지로 돌아가고, 생성·수정·삭제 후 서버 목록을 다시 조회하도록 했습니다.

## 로그인 401

사용자가 확인한 실패 요청은 `POST /manage/sign-in`입니다. 이는 서버가 로그인 요청 자체를 거절한 것입니다. 로그인 이후의 `/manage/me` 검증 실패와는 구분해야 합니다.

프론트의 로그인 요청은 명세에 맞게 `{ loginId, password }` JSON을 보내며 로그인 전에 Bearer 토큰을 붙이지 않습니다. 개발 모드의 동일 출처 `/api` 프록시 연결도 자동 테스트와 실제 `/api/state` 호출로 확인했습니다.

기존 코드는 오류 응답 본문을 즉시 취소했습니다. 이 처리가 브라우저에서 `ERR_ABORTED` 표시에 영향을 줄 수 있어, 작은 오류 본문은 크기를 제한해 끝까지 읽고 폐기하도록 변경했습니다. 서버 내부 오류 원문은 화면에 노출하지 않습니다. 이 수정은 서버가 반환한 401 자체를 성공으로 바꾸지 않습니다.

이제 로그인 자체가 401이면 이메일·비밀번호·계정 활성 상태를 확인하도록 표시하고, 로그인 직후 계정 확인이 실패하면 별도 안내를 표시합니다. 정확한 로그인 거절 사유는 해당 401의 `detail`/`message` 또는 서버 로그 확인이 필요합니다. 계정 생성이 앞서 실패했다면 계정이 저장되지 않아 로그인도 실패할 수 있습니다.

## 다른 기능에서 수정한 사항

- 의사 생성 후 총인원이 갱신되지 않고 페이지당 행 수를 넘길 수 있었습니다. 생성 후 첫 페이지를 다시 조회하고 총인원과 페이지 크기를 맞춥니다.
- 의사 등록·수정·발급 완료 창에서도 오류가 배경 화면에 가려질 수 있었습니다. 현재 작업창 안에 오류를 표시합니다.
- 정지 상태의 의사에게 새 PIN을 발급하는 버튼을 비활성화했습니다.
- 의사 상세·목록, 계정 목록에서 오래된 요청의 응답이 최신 조회 결과를 덮어쓰지 않도록 했습니다.
- 비어 있는 의사 목록과 한도 입력 실패에도 안내를 표시합니다.

## 아직 확인이 필요한 항목

1. 운영 계정의 `/manage/sign-in` 401 사유와 정상 로그인. 유효한 계정으로 수행한 실제 인증 결과가 없어 해결됐다고 판단하지 않았습니다.
2. 인증 후 실제 DB에서의 생성·수정·삭제·한도 부여·PIN 발급 결과, 발급 이메일 및 실제 환자 PDF 표시. 테스트는 모의 응답을 사용하며 운영 데이터를 변경하지 않았습니다.
3. 연결된 브라우저가 제공되지 않아 모바일·데스크톱의 실제 시각 검수는 수행하지 못했습니다. PDF 파일 요청·다운로드·오류 처리는 검사했지만 실제 캔버스 렌더링은 확인하지 않았습니다.
4. 인접 `api` 문서에는 임시·새 비밀번호가 12~128자라고 적혀 있고, 현재 프론트와 README에는 8~64자 및 조합 규칙이 적용돼 있습니다. 공개 OpenAPI 경로는 404여서 현재 서버 규칙을 확인하지 못했습니다. 현재 비밀번호 정책은 임의로 완화하지 않았습니다. 서버의 최신 규칙과 문서를 대조해야 합니다.
